# 0.1.286b

## 活动开始黑边闪烁 2-3 次 根因修复

### 问题
灵动岛实时活动**刚启动时**黑框闪烁 2-3 次，稳定后不再闪。
根因（逐行代码 + 项目自身提交记录交叉验证）：

1. **主因 — host 切换滤镜销毁循环**
   Spring 展开/收缩动画中系统重排 curtain 祖先链 → `LGDIHostForCurtain`
   返回新 host → `LGDIDoScheduledSync` 走 `removeFromSuperview` 重装路径。
   每次重装触发 `LGLiveBackdropView.didMoveToWindow(nil)` → `layer.filters=@[]`
   （render server 销毁捕获组，1-2 帧无滤镜）+ `didMoveToWindow(win)` →
   `applyFilters`（重建滤镜，首帧采样未就绪）。
   弹簧弹跳 2-3 次 = 2-3 次重装 = 闪烁 2-3 次，与症状精确对应。
   独立 DisplayLink（a43faf8）只保护 driver 稳态，不保护活动启动阶段。

2. **辅因 — 展开玻璃首帧滤镜未真正挂上**
   `LGDIEnsureExpandedGlass` 创建玻璃时 `init` 内 `applyFilters` 可能 early
   return（捕获组未 ready），真正挂滤镜依赖 0.2s 延迟 `lgForceRefreshBackdrop`，
   中间 0.2s 窗口展开卡片无液态玻璃 = 黑底透出。

3. **堆积 — 延迟刷新回调堆积**
   锁定期（driver 刚启动）内多个延迟回调各自 0.2s 递归重试，锁定期结束瞬间
   同时命中"未锁定"分支 → 多次重采样 → 黑边闪。

### 修复

| 编号 | 改动 | 文件 |
|------|------|------|
| P0-1 | 新增 `lgSetReparenting:` 标记；`didMoveToWindow(nil)` 命中 reparenting 时跳过 `layer.filters=@[]` 清空，保留捕获组不销毁 | LGLiveBackdropView.{h,m} + DynamicIsland.x |
| P0-2 | pill 玻璃 host 切换重装前 `[sLGDIGlass lgSetReparenting:YES]`；展开玻璃 host 切换前同样标记 | DynamicIsland.x (LGDIDoScheduledSync / LGDIEnsureExpandedGlass) |
| P0-3 | 展开玻璃创建后立即检查 `layer.filters.count`，为 0 则同步 `applyFilters`，消除 0.2s 滤镜未挂窗口 | DynamicIsland.x (LGDIEnsureExpandedGlass) |
| P1 | `LGDIDelayedRefreshBackdrop` 锁定期内不再递归重试，改全局 `sLGDIDelayedRefreshPending` 标记，锁定期结束后由下一个非锁定回调统一触发一次（消除 3-4 个回调堆积） | DynamicIsland.x |
| P2 | host 切换重装后立即同步 `LGDISweepView` + `LGDIStripNearBlackSubtree`（不等 dispatch_async），防新 container 近黑背景透出 1-2 帧 | DynamicIsland.x |

### 不采用的修复（查证后判定为死代码）
- CAFilter 未注册 pending 重试：`registerCustomFilter` 在 backboardd 进程启动
  （`__attribute__((constructor))`）时完成注册并广播 `kLGParametersReloadedNote`，
  远早于任何活动启动。活动启动时 filter table 必然就绪，该路径不会命中。
  引入跨进程时序依赖风险大于收益，跳过。

### 行为说明
- 拆除路径（`LGDITeardown` / `LGDIDestroyExpandedGlass`）的 `removeFromSuperview`
  仍走原清空逻辑（非 reparenting），正确——真正离屏时省电是必要的。
- `_lgReparenting` 在 `didMoveToWindow` 两个分支（nil/win）都会复位为 NO，
  不会残留。
- 重新挂载时 `applyFilters` 走 early-return（`_filterAttached` 仍 YES 且
  `layer.filters.count==1` 且基类型相同），不重建捕获组，黑边消除。

### C8 联网查证修正（2026-09-12）
对 P0-1 的 reparenting 方案做联网查证后，修正 2 处 + 1 处降级：

1. **降级**：原注释"`_lgGroupName` 带 .e<epoch> 单调递增 → render server 建新
   捕获组"——经查证，`CABackdropLayer` 的 `groupName` 复用/唯一语义**公开资料
   查无实据**，很可能是原作者基于黑盒现象的经验总结。kageroumado/
   core-animation-private（macOS 侧 CA 私有 API 逆向，共享 QuartzCore 命名）
   证实 `backdrop groups` 是真实私有概念，但未证实"复用同名 → 归到陈旧捕获
   组 → 永久发黑"这条因果链。**修复不再依赖 .e<epoch> 兜底**。

2. **新证据（部分确定）**：kageroumado 明确记录"first cross-window move →
   portal renders blank until compositing connection settles"，解法是
   `refreshConnection()`（无动画事务内切 sourceLayer off/on 再 on）。这反向
   支持 P0-2/P2 方向正确，且要求在 reparenting 的 win 分支**手动 nudge**
   捕获组重关联。

3. **修正已写入代码**：
   - remove 阶段（`didMoveToWindow(nil)` reparenting 分支）去掉多余的
     `LGRefreshMotionHighlights()`（保留滤镜就不该触发高光重算），改为
     仅 `setNeedsDisplay` 强制重采样。
   - insert 阶段（`didMoveToWindow(win)` 分支）reparenting 时额外
     `setNeedsDisplay`，弥补 `applyFilters` early-return 不触发重采样、
     捕获组可能未重关联到新 window 上下文的问题。

4. **无法确定项（不编造，需真机验证）**：
   - render server 在跨 window reparent 时捕获组是否自动重关联——公开
     资料查不到，只能靠 `setNeedsDisplay` nudge + 真机观察。
   - spring 弹跳次数与 host 重装次数是否 1:1 对应——取决于系统祖先链
     重排节奏，无法公开查证；只能确定"重装 N 次 = 闪 N 次"机制成立。
   - "Mango" tweak 是否存在/可作参考——公开 GitHub 未找到，无法核验。

# 0.1.287b 追加修复（用户反馈后）

用户反馈 0.1.286b 修复后仍存两个问题：

## 问题1：活动灵动岛边缘黑框闪烁仍存在
**根因**：展开玻璃/pill 玻璃 host 切换走 `removeFromSuperview + insertSubview:aboveSubview:`，
**同 window 内换 superview 时 `didMoveToWindow(nil)` 和 `didMoveToWindow(win)` 都不触发**
（self.window 始终非 nil），reparenting 标记用不上；`layer.filters` 虽保留但
render server 捕获组未重关联到新 superview 几何 → 边缘采样错位 = 黑框闪。

**修复**：新增 `LGLiveBackdropView.lgNudgeCaptureReattach`（软刷新，不替换
layer.filters 数组避免 1-2 帧无滤镜黑边），在展开玻璃和 pill 玻璃 host 切换
重装后调用。

## 问题2：展开灵动岛关闭时液态玻璃延迟残留阴影
**根因**：`LGDIDestroyExpandedGlass` 拆除时 `@try` 块只清 `glass.layer.filters`
+ `glass.layer.groupName`，**漏清 `_nativeBlurLayer`**。而 `_nativeBlurLayer`
是挂在 `glass.layer` 上的第二个独立 CABackdropLayer 捕获组（带 .nativeblur
后缀 groupName，独立 windowServerAware 配置），是玻璃原生模糊底板。
`removeFromSuperview` 后 glass 对象仍被 sLGAllGlasses 弱引用表 + 本地变量强引用
持有，dealloc 前 1-2 帧 `_nativeBlurLayer` 仍在 render server 侧合成 →
液态玻璃折射/高光残留 = "延迟阴影"。

**修复**：新增 `LGLiveBackdropView.lgTeardownCaptureGroup`（无动画事务内
原子清 layer.filters + _nativeBlurLayer + groupName + setNeedsDisplay），
`LGDIDestroyExpandedGlass` 调用它替代旧的 @try 清理。
